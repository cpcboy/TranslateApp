# SENSE

macOS 上的 AI 翻译器。查一个词，给一张完整的义项卡——音标、按常用度排序的义项、场景化例句；长文给逐处批注；截图给即时解析。不做聊天框。

**当前进度：M1 已完成（D1–D5）**。查词闭环可用，截图与校对还没做。

## 现在能做什么

- `⌃⌥⌘Space` 在任意 App 下调出 / 收起窗口（Rust 侧注册的全局快捷键）。键位可改，见下方「改快捷键」
- 无边框、透明、置顶、居中的 960×900 窗口；双击启动就能看到，按 Esc 收起
- 左上角三颗灯：红 = 退出应用（等同 ⌘Q；会丢掉只在内存里的内容，比如正在翻译的长文，快捷键也不再响应）、黄 = 隐藏窗口（同 Esc，快捷键还能再呼出）、绿 = 放大到屏幕可用区域 / 再点还原
- 四条边、四个角都能拖着缩放（最小 760×720），抓可见的边框就行。原来系统自带的缩放区只有窗口最外缘约 3px 一圈，藏在 12px 的透明边距里，看不见也不好抓；新加的 8 个把手覆盖到面板内 4px，见 `src/features/window/`
- `⌘+` / `⌘-` / `⌘0` 放大 / 缩小 / 还原界面字号（70%–160%，每次 10 个百分点；`⌘=` 也行，小键盘的 + - 0 也行）；缩放整张面板的内容，记住上次的字号
- 自动更新：后台每 6 小时去 GitHub 看有没有新版本，有就下载并校验签名，下载好后窗口顶部提示「立即重启」；设置页有「更新」卡片（当前版本、手动检查、自动检查开关）。Apple 芯片和 Intel 各一个包。见下面「自动更新」
- 失焦自动隐藏（260ms 宽限期，避免「刚呼出就自己藏起来」）
- `Esc` 隐藏
- 查词：Enter 触发，模型流式返回，卡片边到边渲染（首个完整义项就画，不等整包）
- 四个 provider 预设（DeepSeek / 通义千问 / OpenRouter / Ollama）+ 自定义 base_url
- Key 只进钥匙串，设置页只回显 `sk-****abcd`
- 「测试连接」测的是表单里**当前的值**（地址、模型、刚填还没保存的 Key），都不落盘；和已保存的不一样时，结果后面会注明「测的是表单里还没保存的值」
- 查过的词落本地 SQLite，第二次查询 0 网络请求；最多留 5000 条，超出时先淘汰已标过期的、命中最少的、最旧的
- 输入英文词就解析这个词；**输入中文，会先译成英文，再解析那个英文词**（输入「充电」，卡片是 recharge 的义项、IPA 和例句，标题上方标着「充电 → 英文」；中文词还有别的常见译法时写在备注里）。模型没按要求译成英文时，重试一次，仍不行就照样展示中文词条并在卡片上方明说。
- 输入框里是一个词、词组、成语就查词典；一句话以上、多行、日文韩文、超过 64 个字符，自动进入长文翻译（英文超过 8 个词，或 3 个词以上带句末标点；中文超过 12 个字，或 9 个字以上带逗号顿号分号句号，或 8 个字以上以句末标点收尾；缩写点 Dr. / Sen. / Inc. / etc. / Ph.D. 不算句末）。8 个字以内的成语、谚语、短问（`画蛇添足。`、`塞翁失马，焉知非福`）仍查词典，8 个字以内的完整短句（`我不知道。`）也会进词典；英文短语后面加了句号会被当成句子，去掉标点就是查词。规则在 `src/lib/route.ts`，有单测

## 截屏翻译

按 `⌃⌥⌘X`，拖一个框，松手即可。（入口只有这个快捷键，主窗口里没有截屏按钮。）

- 文字用 macOS 自带的 Vision 识别（离线、不出本机、不花钱）；中文、英文都读得出来：每张图用「中文优先」「英文优先」各识别一遍，图里有真中文就用前者，否则用后者（不含中文的图，识别结果和只做英文优先时完全一样）。识别时间比以前长约一倍
- 翻译走你在设置里配的模型
- 译文**盖在原来的位置**上，用**原文的字号和颜色**，底色取自原图（不再是一块黑底）；点一下或 Esc 关闭
  - 字号按原文反推：对每个词量出「在哪个字号下恰好这么宽」，同款字号的几行画成同一个大小
  - 译文和原文一样的（命令、版本号、专有名词）不重画，原像素原样保留；全都一样时覆盖层会说一声
  - 译文比原文长时先往右边的空白里延伸，不够再缩小（最多缩到 0.75 倍），仍放不下就截断、加省略号并标出来
  - 表格线、分隔线、隔壁的色块不会被盖掉；渐变底用一块平色填充（会看到一块浅浅的补丁）
  - 已知限制：粗体画成常规字重、等宽字体字号偏大约 20%、图标被读成 `©` `•` `@` 的字符会带进译文，见 CHANGELOG
  - **折成多行的中文段落合成一块再翻译**：一句话被折成几行（软换行）时，按版面认出「写满一行、话没说完、读起来像正文（有逗号句号）、字色一样」的行，合成一块交给模型，译文按原来的行距折行；汉字之间接起来不加空格。菜单、侧栏、表格、标签、按钮、标题、文件名这些**没有逗号句号**的行，新的中文判据一对也合不了（英文那条老路没动：下一行以小写字母开头的行它照样会合并，例如 `最近使用的项目` + `iCloud 云盘`，这是以前就有的）。宁可漏合、不可错合，所以下面这几种仍然各译各的：第二行很短又没有句末标点的两行段落、起手两行里一个句号问号叹号都没有、后面的行也没有写满或句号收尾来印证的折行（新闻标题 / 摘要）、绕着图片 / 信息框排的窄段落（同列里别处有更宽的行）、被引用上标撑高的行、字色不同的两行（标题 + 灰色摘要；整行是链接色的行会把一段切开）、居中的文字、上一行恰好以句号收尾。反过来，几何和标点上和折行一模一样的独立行仍可能被合并：字色字号都一样的「标题 + 一句话摘要」、两条等宽的标题加一条以句号收尾的短行，残余风险和数字见 CHANGELOG
  - 中文截图的已知限制：单个汉字的按钮读不出来；日文、韩文、竖排文字读不出来；整页塞满方框图标 / 符号的图偶尔会被当成中文（英文单词多几处读错、图标位置多出几个汉字）；译文（英文）比中文长很多时会缩小或截断（合并成段的块只能放原来那么多行，超长的译文更容易被截断），见 CHANGELOG
- 翻译失败（比如还没填 Key）时，覆盖层顶部会写明原因，下面画的是识别出的原文，不会冒充译文
  - **一次框住的文字块太多（超过 40 个）时，约 4 成请求会因为「译文条数对不上」整次失败**：模型把被拆开的半句话并回了邻条，条数一少，应用就不敢把译文按位置套回去（覆盖层写明原因）。这不是每次随机的概率，而是看版面：侧栏 / 目录与正文穿插的整页多半失败，同一个框再试多半还是失败（同一输入失败后再发一次，DeepSeek flash 约 2 成能成，默认的 deepseek-chat 不到 1 成）；把框收到正文那一栏、避开侧栏更可能成功（没有专门测过）。用 DeepSeek 实测：40 个文字块以内的整页 0 / 36，合成的小区域（阅读顺序里的几条，不是真拖框）约 7%。核对过提示词没有让模型删减整段内容（没改）；改措辞只能压低一部分条数对不上，还带来别的问题（没采用），数据和试过没采用的对策见 CHANGELOG「验证 · 2026-10-31 — 截屏翻译提示词」
- 覆盖层大小以截出来的图片为准，位置由鼠标按下的那个角和拖动方向推算。拖动时按了空格、⇧、⌥，或者切到了窗口模式，位置就推不准：这时覆盖层放在鼠标附近，底部会写明「不一定对准原文」
- 截屏还没结束时再按快捷键会被忽略（不会开出第二个选框）；上一次的译文窗口会先被收掉，不会被拍进这一次的截图

### 屏幕录制权限（注意）

首次使用要授权：**系统设置 → 隐私与安全性 → 屏幕录制 → 勾选 SENSE**，
然后**退出并重开 SENSE**（macOS 只对新进程生效）。

> **为什么授权了还是不行**：SENSE 现在是 ad-hoc 签名（没有 Apple 开发者证书），
> 每次重新构建，二进制都会变，而 macOS 这条授权记录绑的是**那一次构建的二进制**。
> 系统设置里开关看着是开的，对新构建其实无效。
>
> 重新构建之后，跑一次：
> ```bash
> ./tools/grant-screen-recording.sh
> ```
> 它会清掉旧记录并重启应用，下次按 ⌃⌥⌘X 时系统会为当前这份重新弹窗。
>
> 拿到开发者证书后（或自签一张「代码签名」证书并签名），这个问题会消失。

出问题时看日志：`~/Library/Application Support/com.sense.app/capture.log`
（权限、截图返回码、OCR 行数、翻译块数都记在里面）。

> OCR 组件是构建时用 `swiftc` 编的 sidecar（`tools/ocr.swift`），产物 `src-tauri/binaries/` **不入库**，
> 克隆下来第一次构建时由 `build.rs` 现编。没有 Xcode 命令行工具（`xcode-select --install`）也能构建：
> 这时放一个占位脚本，截屏翻译会如实报「OCR 组件没有编译成功…」。设 `SENSE_SKIP_OCR=1` 可以主动跳过编译。

## 改快捷键

设置页 →「快捷键」→ 点「修改」→ 直接按新组合，立刻生效。

- 至少包含 `⌃` 或 `⌘`
- 主键支持字母、数字、空格
- 两个功能不能用同一个组合
- 注册失败（被别的 App 占了）会把旧键装回去
- 配置里写的键如果启动时没注册上，设置页会标「未生效」（不再照着配置文件显示一个按不出来的键）；改完查词键，标题栏的键帽立刻跟着变

## 长文阅读

输入超过 64 字自动进入阅读视图：左侧原文、右侧译文，边生成边显示。

| 操作 | 效果 |
|---|---|
| `Esc` / 「← 返回查词」 | 退出阅读视图（不会收起窗口）；释义浮层开着时 Esc 只关浮层 |
| 选中词 / 词组后松开鼠标 | 弹出该词在**当前语境**下的意思 |
| 选中后 `⌘⇧D` | 同上，键盘可达 |
| 「停止」 | 中断生成，已生成部分保留 |
| 复制原文 / 复制译文 | 写入剪贴板 |

英文原文会在译文完成后自动做语法检查，错误处用**虚线下划线 + 橙色**双编码标出，
悬停看解释与改法。每条问题只标原文里第一处整词命中的位置（不会把 good、ago 里的 go 也标上）。撞到输出上限时右栏底部会给出「可能不完整」的提示。
选中词弹出的释义，上下文取选中词前后各 200 字；同一个词在同一段话里再选一次直接用上次的答案，不再多发一次请求。

没有正常写完时（断网、服务端掐断或提前收工、超时、你点了「停止」），右栏末尾会标「译文不完整」并写明原因，可以「重新翻译」。
离开阅读视图或开始新的查询，会顺手停掉还在生成的长文，不会在后台继续计费。
长文没有 180 秒上限：流式请求按输出上限单独放宽，只有卡住才算超时（8 秒没出第一段，或连续 90 秒没有新内容）。
点「停止」之后立刻标「不完整」，也不会再对被放弃的译文发语法检查请求。

## 速度

查词默认**关掉模型思考**（DeepSeek 的 thinking 默认是开的，effort 还是 high，
不关的话每次要先吐几千 token 的思维链）。

| 场景 | 预期 |
|---|---|
| 同一个词第二次查（缓存命中） | 0 请求，瞬时 |
| 新词，第一个义项出现 | 网络 RTT + prefill，通常 1–1.5s |
| 新词，五个义项全部到齐 | 3–6s（受模型生成速度限制） |

页脚会显示 `首义项 … · 总计 …`，这是真实测量值，不是估算：

- `首义项`：从回车到第一个完整义项可渲染（含解析与渲染）
- `总计`：整包收完

> 500ms 出完整卡片是做不到的：光到 `api.deepseek.com` 的往返实测就 ~330ms，
> 再加五个义项的生成时间。能压到 500ms 以内的只有缓存命中。

各家关思考的写法不同，改在 `providers::reasoning_fields`；
如果某个中转网关不认这些字段（返回 400），会自动去掉再试一次，并在本次运行里记住这家网关不认、之后直接不带。查词、长文、语法、划词、截屏五条链路都一样。

## 装成 App（推荐，日常用）

```bash
./tools/install-app.sh
```

它会构建、把 `SENSE.app` 拷进 `/Applications`、关掉旧进程再启动。之后从启动台/访达双击即可，
不需要开终端。应用没在运行时快捷键当然不会响应——这是全局快捷键的常识，不是 bug。

> 目前没有登录项，重启 Mac 后需要手动打开一次（D13 会加）。

## 自动更新

装了带更新器的版本之后，应用会自己去 GitHub 看有没有新版本：有，就在后台下载并校验签名；下载好后窗口顶部出现「新版本 vX 已下载好。点「立即重启」完成更新」，点了才替换并重启（约 2 秒）。**自己退出再打开不会更新**：下载好的包只放在内存里，不点「立即重启」就继续用现在这一版，下次启动会重新下载。设置页的「更新」卡片可以看状态、手动检查、开关自动检查。

- **什么时候检查**：启动 30 秒后一次，之后每 6 小时一次，失败 30 分钟后重试（按挂钟时间算，合盖睡一夜醒来会立刻补查）。设置页的开关（或 `settings.json` 里的 `"auto_update": false`，缺省是开）关掉后台检查；关了之后手动「检查更新」照常可用
- **为什么要点一下才重启，而不是后台自己重启**：窗口失焦就会藏起来，而长文翻译在窗口藏着的时候还在跑；后台自己重启会丢掉它，也会在你打字的时候把新窗口弹到最前面抢走焦点
- **安全**：更新包用 minisign 签名，公钥写在 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`。签名里还绑着版本号（`requireSignedVersion`），被篡改的清单没法把「新版本号」配上一个旧安装包；校验不过就丢弃、不装任何东西；只升不降。检查、下载、验签、替换都在 Rust 里做，WebView 没有 `updater:*` 权限，只能通过四个命令（状态、立即检查、立即重启、开关）操作，且只认主窗口
- **联网**：清单是 `https://github.com/cpcboy/TranslateApp/releases/latest/download/latest.json`，安装包在同一个 Release 里；GitHub 会把下载**重定向到它的下载域名（`*.githubusercontent.com`）**，所以排查防火墙 / 代理时这两类域名都要放行。下载地址必须和清单端点同源，否则当作被篡改拒收。仓库是公开的，应用里没有任何 token；没有自建服务器（硬约束 4）。国内网络直连 GitHub 可能慢或不稳：检查超时 20 秒、下载最多等 15 分钟，失败了设置页会写原因，30 分钟后重试（验签失败这类「发布出了问题」的失败退到下一个 6 小时）
- **代理**：更新器和模型请求（查词、截屏翻译……）一样，只认环境变量里的代理（`HTTPS_PROXY` 等），**不读**「系统设置 → 网络 → 代理」。从启动台 / 访达打开的应用没有这些环境变量，等于直连——直连 DeepSeek 这类服务时，模型请求不会被系统代理绕路。更新插件的默认特性 `system-proxy` 会让进程里所有 `reqwest` 客户端（包括模型请求）去读系统代理，所以 `Cargo.toml` 里关掉了它（`default-features = false`），守卫用例 `updater_plugin_does_not_turn_on_the_system_proxy` 查两处：插件依赖那一行、`Cargo.lock` 里不能出现 `system-configuration`。代价：只靠系统代理才能打开 `github.com` 的电脑，自动更新会失败（设置页会写原因），要手动下载新版本
- **体积**：加了更新器之后 `SENSE.app` 从 9.31 MiB 变成 10.09 MiB（+0.78 MiB）；更新包 `.app.tar.gz` 是 5.2 MB（Apple 芯片）/ 5.8 MB（Intel）
- **怎么替换**：解到 `.app` 同一个磁盘上的临时目录，再用 `renamex_np(RENAME_SWAP)` 原子交换两个 `.app`，中途任何一步失败都会还原，旧版本不会丢；装在 `/Applications` 里而当前账户没有写权限时，才会弹系统的管理员授权。换好之后用 `open -n` 拉起新的并确认它起来了（没起来最多重试 3 次）
- **不能更新的情况**（设置页会写明原因，不会假装在检查）：开发版（debug 构建）、不是从 `.app` 里运行的、从下载目录 / 磁盘映像里直接打开的（macOS 会把它临时挪到只读位置，先拖进「应用程序」再打开）
- **日志**：`[sense] update: …`。从 Finder 启动看不到终端输出；要看就先退出 SENSE，再在终端跑 `open -n --stdout /tmp/sense.log --stderr /tmp/sense.log /Applications/SENSE.app`，然后看 `/tmp/sense.log`（启动 30 秒后会有第一次检查的结果）。重启那一步由一个独立的小进程接手，它的记录在 `~/Library/Logs/SENSE-update.log`——点了「立即重启」却没看到新窗口，先看这个文件
- **更新说明**：Release 的说明（`--notes-file`）按**纯文本**显示在设置页的「更新」卡片里，最多 600 个字符，多的截断
- **「稍后」**：只收起这一版、这一条错误的横幅；窗口再被呼出（拿到焦点）时再出现，出了更新的版本、出了新的错误也会再出现。横幅的三种样子：已下载好（立即重启 / 稍后）、正在安装、更新需要你处理（安装或重启没成而且包已经不能再试，比如旧版本没放回原位，只有「知道了」；点了「知道了」才会放掉，后台的下一次检查不会把它悄悄抹掉）
- 设置文件里多两个字段：`auto_update`（开关）和 `last_update`（最近一次更新的 `{from, to, at}`，装好重启前写下，设置页据此显示「最近一次更新」）

### 发布新版本（维护者）

产物是两个包（Apple 芯片 `aarch64`、Intel `x64`）加一份 `latest.json`，都发在 GitHub Release 上。**一条命令构建，发布要你另外确认**：

```bash
# 1. 改版本号，四处必须一致：src-tauri/tauri.conf.json、src-tauri/Cargo.toml、src-tauri/Cargo.lock（在 src-tauri 里跑一次 cargo check，它会自己更新）、package.json。提交，再 push（push 要单独授权）
# 2. 只构建，不上传任何东西：产物在 dist-release/
./tools/release.sh --notes-file notes.md      # notes.md 是更新说明，应用里会显示；不写就是「SENSE vX.Y.Z」
# 3. 确认没问题再发布（必须在交互式终端里运行，会让你亲自输入 yes；发布前核对 HEAD 已在 origin/main、这个版本没发过）
./tools/release.sh --publish --notes-file notes.md
```

这个 `yes` 不是安全边界：脚本只是不让管道 / 无人值守的进程喂进去（`--publish` 不在交互式终端里直接拒绝，在构建之前）。真正的控制是：创建 Release 每次都需要负责人当次授权。

脚本做的事：**开头**就核对版本号四处一致、`tauri.conf.json` 里的更新安全开关没被关（`requireSignedVersion`、不开明文 http）、私钥权限是 600 且和配置里的公钥一致、`SENSE Dev` 证书的 SHA-1 指纹对得上；`--publish` 的前提（`origin` 就是本仓库、`gh` 已登录、HEAD 已在 `origin/main`、这个版本没发过）也在构建之前查，不等构建完才发现。然后跑 `npm run typecheck`、`npm test`、`cargo test --locked`，不绿就停；两种芯片各构建一次（`--locked`），核对芯片、OCR 辅助程序的最低系统版本、主程序里带着配置里的更新公钥；用 `SENSE Dev` 签名（与 `install-app.sh` 同一种签法）；打成 `.app.tar.gz`，审一遍里面的成员（没有 `._` 附属文件、没有路径穿越）并解包回来再验一次签名；用更新私钥签名并绑定版本号；生成 `latest.json` 并核对；**用应用里写死的公钥给两个包真的验一次签**（`node tools/update-manifest.mjs verify …`，也可以单独拿来验任何一个 Release）。发布后把线上的 `latest.json` 和它指向的两个安装包下载回来，再用同一把公钥验一遍。

**第一次发布，以及怎么验证真实的更新链**：现在的版本号 0.1.0 就是带更新器的第一个版本。**更早装在其他电脑上的 SENSE 没有更新器，不会自己更新**，每台要手动装一次这个版本（见下面「在另一台电脑上第一次安装」）。所以：

1. 先发 `v0.1.0`（上面的 3），在另一台电脑上手动装好；
2. 再把版本号改成 `0.1.1`（四处）、提交、push，发 `v0.1.1`；
3. 那台电脑上的 SENSE 会在 6 小时内自己发现并下载（也可以在设置页点「检查更新」立刻触发），窗口顶部出现「立即重启」，点它，应用以 0.1.1 重新打开，设置页写着「最近一次更新：v0.1.0 → v0.1.1」。

这条链上下载走的是真的 GitHub（CDN 重定向）、真的管理员授权弹窗（如果那台电脑上装在 `/Applications` 里而账户没有写权限）——这些是本机演练碰不到的，值得在这一步亲眼看一遍。

**一次性准备**：

1. 更新签名密钥（**这台电脑上已经生成**：2026-11-01，`~/.tauri/sense-updater.key`，权限 600，**没设密码**）。「无密码」是 AI 在负责人说「太麻烦了，不用密钥吧」之后替他选的，负责人随后（2026-11-01）明确回复「接受无密码」；第一个 Release 发出去之前仍可以换成带密码的（重新生成、把新公钥填进 `tauri.conf.json`、重跑测试）。私钥只存本机，**不要入库、不要贴进聊天**（`.gitignore` 兜着 `*.key`，`release.sh` 拒绝放在仓库目录里的私钥）：丢了，已装的机器就再也收不到更新（只能手动重装）；泄露了，别人只要还能控制更新端点就能给所有已装机器推更新；没有密码，所以谁能读到这个文件谁就能签——**请自己备份 `sense-updater.key` 和 `sense-updater.key.pub` 两个文件**（密码管理器 / 加密备份盘；`.pub` 丢了可以把 `tauri.conf.json` 里的 pubkey 原样写成它，`release.sh` 没有它会直接失败）。发布时 `release.sh` 会问私钥密码，没设密码就直接回车（或 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD= ./tools/release.sh`）。
   换一台电脑发布：把这两个文件拷过去、私钥权限改成 600 就行。**不要重新生成**——新密钥就是新公钥，换钥的代价见下面「更换更新密钥、私钥丢了或泄露了」。真要重新生成：
   ```bash
   cd sense && npx --no-install tauri signer generate -w ~/.tauri/sense-updater.key   # 会问密码，可以直接回车；加 --ci -p "" 免交互
   ```
2. 公钥（`~/.tauri/sense-updater.key.pub` 的内容）**已经原样填在** `tauri.conf.json` 的 `plugins.updater.pubkey`（密钥 ID `3A956737A622F6D6`）。`cargo test` 里有一条用例检查它是不是合法的 minisign 公钥（不是占位）；`release.sh` 比对它和 `.pub` 文件一致，并用它给签出来的每个包真的验一次签（私钥与公钥不配对会在这里被拦下，而不是等装机的人发现）。**已装机器信的就是随安装包发出去的这个公钥**——换密钥要走过渡版本，私钥丢了则只能手动重装（见下面「更换更新密钥、私钥丢了或泄露了」）
3. 钥匙串里要有 `SENSE Dev` 代码签名身份：升级前后签名身份不变，屏幕录制授权和钥匙串里的「始终允许」才不会在每次更新后掉光。脚本按证书的 SHA-1 指纹（`9F6C3A9C…B3EA4F0`，写在脚本里，`SENSE_SIGN_IDENTITY_SHA1` 可改）认它，找不到、或钥匙串里出现了同名的另一张证书，都拒绝发布，不会悄悄退成 ad-hoc 或换一张证书
4. `rustup target add aarch64-apple-darwin x86_64-apple-darwin`；`gh auth login`（发布用）

### 更换更新密钥、私钥丢了或泄露了

已装的机器用**自己配置里的公钥**（`tauri.conf.json` 的 `plugins.updater.pubkey`，随安装包发出去）验签，所以：

- **第一个 Release 还没发之前**不存在这个问题：直接重新生成、把新公钥填进配置、重跑测试。
- **主动换钥（旧私钥还在，比如想给私钥加密码）**：理论上可以先发一个过渡版本——用**旧**私钥签名、但配置里写**新**公钥；已装机器升上去之后就只信新钥，之后的版本用新私钥签。`release.sh` 要求「配置里的公钥 = 私钥旁边的 `.pub`」并用配置里的公钥验每个包，这种组合会被它拒绝，过渡版本要手工签名、手工生成 `latest.json`；**这条路没有演练过**，真要走先在演练模式里试一遍。
- **私钥丢了**：旧公钥永远验不过新签名，已装机器收不到任何更新，只能手动重装一个新版本（里面是新公钥）。
- **私钥泄露了**：拿到私钥还不够，对方得能把假包放到更新端点上（GitHub 仓库的写权限，或者劫持下载链路）。先收紧 GitHub 账号（改密码、撤销可疑的授权和令牌）、检查 Releases 里有没有不认识的版本；旧钥已经不可信，过渡版本也救不了（对方同样能用旧钥签），要换新钥发新版本，并通知大家手动重装。

### 已知限制

- **防不住冻结和重放**：没有服务端状态，能控制清单页、但没有签名私钥的人，可以一直给出一份旧的、真签过名的清单让机器停在某个版本，或重放一个版本号比当前高的旧包；做不到降级、也装不上没签名的东西
- **更新器不读 macOS 系统代理**（为了不动模型请求，见上面「代理」）：只靠系统代理才能打开 `github.com` 的电脑，检查更新会失败（设置页写「连不上 GitHub（网络不通；注意：更新检查不读系统代理）」），要手动下载新版本；从终端启动、带着 `HTTPS_PROXY` 时，更新器和模型请求一样会走它
- **macOS 11 / 12**：主程序能打开、查词可用，但截屏翻译需要 13（OCR 辅助程序按 13 的下限编译），会报晦涩的 dyld 错误。没把整个应用的最低版本设成 13，那样 11 / 12 上连查词都用不了
- 管理员授权弹窗（装在 `/Applications` 而当前账户没有写权限时）、磁盘写满、下载一半断开、睡眠唤醒后的补查，都还没在真机上验过

### 在另一台电脑上第一次安装

自动更新只管「已经装了的」；每台电脑第一次要手动装一次：

1. 在 [Releases](https://github.com/cpcboy/TranslateApp/releases) 页下载对应芯片的包：Apple 芯片（M1 及以后）选 `SENSE_<版本>_aarch64.app.tar.gz`，Intel 选 `SENSE_<版本>_x64.app.tar.gz`（不确定看「关于本机」）
2. 双击解压，把 `SENSE.app` 拖进「应用程序」文件夹（**一定要拖进去再打开**，直接在下载目录里打开会被系统临时挪位置，之后更新装不进去）
3. 第一次打开会被 Gatekeeper 拦下（自签名、没有公证）：在终端跑 `xattr -dr com.apple.quarantine /Applications/SENSE.app`，或在「系统设置 → 隐私与安全性」里点「仍要打开」。这一步更新器解决不了；正式的「开发者 ID 签名 + 公证」留给 D14
4. **每台电脑要自己填一次 API Key**：Key 只存在本机钥匙串里，不随应用走，也不会同步
5. 截屏翻译需要在「系统设置 → 隐私与安全性 → 屏幕录制」里给 SENSE 授权，并且需要 **macOS 13 及以上**（Vision 的中文识别从 13 起才有；辅助程序按 13 的下限编译）

### 撤回一个有问题的版本

- 还没人更新到：把那个 Release 改成「预发布」（或删掉）。`releases/latest` 就退回上一版，没更新的机器看到的还是上一版；**已经下载好、还没重启的机器，下次检查发现清单里没有它了，会把它丢掉**
- 已经有机器更新到了：不能降级（更新器只升不降）。修好之后发一个更高的版本号，它们会自己升上来。如果坏到连更新器都起不来，只能手动重装任意一个好版本
- 想固定在某个版本：把设置页的「自动检查并下载」关掉

### 改快捷键

快捷键存在配置文件里，改完重启应用即可生效，不用重新编译：

```
~/Library/Application Support/com.sense.app/settings.json
```

```json
{ "hotkey": "ctrl+alt+cmd+space" }
```

- 修饰键：`ctrl` / `alt`（=option）/ `shift` / `cmd`（=command），用 `+` 连接，顺序随意
- 主键：`space`、单个字母、单个数字
- **必须至少含一个 `ctrl` 或 `cmd`**：只有 shift/alt 的组合（例如 `shift+space`）会抢走所有输入框的按键，会被拒绝
- 写错（缺修饰键、多个主键、JSON 坏掉、字段缺失）会回退到默认 `⌃⌥⌘Space`，终端里打印具体原因，启动日志里会写明这次键位来自哪个文件

> 目录名由 `tauri.conf.json` 的 `identifier` 决定（当前 `com.sense.app`）。改了 identifier 目录就会变，以启动日志里的「来源：…」为准。

> 为什么是 `⌃⌥⌘Space`：`⌥Space` 被 Gemini / ChatGPT 占用；`⌥⌘Space` 既是 macOS 系统符号快捷键（Finder 搜索）又被 Claude 桌面端占用。带 ⌃ 的三修饰键组合不在系统符号快捷键表里。
